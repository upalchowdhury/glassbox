# Legacy files

These are the original implementation, kept for reference. Nothing in the
current package imports them.

## `glassbox_engine.py`

The original single-file engine, superseded by the `glassbox/` package.

It was removed from the project root during the rebuild and has been restored
here unchanged. Its fidelity was verified by re-running it and confirming it
reproduces the original recorded values exactly: vocabulary 34, 2192
parameters, base loss 8.0558 -> 3.3809, validation 3.0876, SFT 2.7737 -> 0.5350,
prose validation 3.8077, finite-difference absolute error 3.4347e-3, and the
SFT checkpoint answering the trained question with `the.................`.

It is kept because it is the subject of the audit that drove the rebuild, and
because those numbers are the "before" side of every comparison. Do not build
on it. Known defects that the rebuild fixes:

| Defect | Effect |
|---|---|
| `nn.Embedding` default `N(0,1)` init with a tied output head | untrained loss 7.37 against `ln(34) = 3.53`, so most of the advertised loss drop was the optimiser undoing an initialisation artefact |
| Loss logged on ONE fixed 32-character window | the displayed training curve *rose* between steps 40 and 400 while the true corpus loss fell |
| No held-out evaluation | a unigram Laplace baseline scored 2.70 against the model's 3.09 - the model lost to counting |
| `generate()` sliced `generated[-32:]` | the 52-token SFT prompt was truncated to its last 32 characters, which is the sole reason the headline answer looked broken |
| `:` absent from the vocabulary | every chat-template delimiter was silently encoded as `<pad>` |
| Unknown characters mapped to id 0 | id 0 is `<pad>`, so typos trained the model to predict padding |
| Windows built over `"".join(paragraphs)` | windows crossed paragraph boundaries while the interface claimed they did not |
| SGD demo mutated `block0_mlp_up.weight` and never restored it | base training began from weights no checkpoint had recorded |
| One SGD dict aliased into all three checkpoints | the checkpoint selector showed random-init gradients while claiming otherwise |
| Temperature divided the logits and then took `argmax` | the control was inert; argmax is invariant to positive scaling |
| Zero `assert` statements | the documentation claimed seven numerical checks existed |

## `Glassbox_Interactive_Starter.html`

The original browser app, superseded by `../app/index.html`. It was moved here from
the project root so there is only one app at the top level; nothing was changed inside it. Its embedded run
data came from a different pipeline than the engine above (vocabulary 50, 2384
parameters) and cannot be regenerated by any code in this repository. Its
flagship "one output cell = one dot product" panel indexed a `[16, 8]` weight
matrix as if it were `[8, 16]`, so 72 of 144 cells rendered `NaN` and the rest
printed a sum that disagreed with the value beside it.
